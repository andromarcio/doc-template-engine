# N3 — Feature

A **especificação detalhada** de uma única funcionalidade (ex.: Calcular Frete,
Cadastrar Cliente).

## O que é (e não é) uma feature

Uma feature é **uma ação de negócio com começo, meio, fim e resultado observável**,
nomeada por **um verbo no infinitivo + uma entidade** (*cadastrar cliente*,
*calcular frete*). "Cadastro de Clientes" agrupa várias ações — isso é um
**Feature Set (N2)**, não uma feature. Campo, regra de negócio, tela, mensagem e
requisito não-funcional também **não** são features (cada um tem seu destino próprio).

A definição canônica e testável — critérios objetivos FD-1…FD-8, vocabulário de
verbos canônicos e termos bloqueados — vive em `engine/FEATURE-DEFINITION.md` e é
verificada **deterministicamente** (sem depender de LLM) pelo gate
`scripts/validate-feature-semantics.mjs`, que roda automaticamente a cada N3 gravado.

## O papel do N3

É o nível que a **equipe de desenvolvimento consome diretamente** para
implementar. Recebe um ID dentro do Feature Set (ex.: `USR-PRM-01` ou `F01`).

## O que contém

Descreve, campo a campo, o comportamento da funcionalidade:

- **Campos** — o que o usuário preenche e vê.
- **Regras de negócio** — as que valem só para esta feature (um critério de aceite que expressa uma **invariante** vira regra).
- **Cenários** — em **Gherkin** (derivados dos critérios de aceite que descrevem **comportamento observável**).
- **Comportamento de tela** — estados, validações e reações.
- **Origem** — a chave da história (ServiceNow) que originou a feature.
- **Implementação** — repositório e caminho do código.

## Artefato

```text
modules/[dominio]/[feature-set]/[feature].md
```

## Como gerar

| Passada | Prompt | Produz |
|---|---|---|
| **A — Negócio** | `PROMPT_3A_N3_negocio` | campos, regras e cenários em linguagem de negócio |
| **A (transcrição)** | `PROMPT_TRANSCRICAO_REUNIAO` | N3 a partir de uma transcrição de reunião (gera ou atualiza; pode tocar N2/N1) |
| **B — Técnico** | `PROMPT_3B_N3_tecnico` | detalhe técnico e **dimensionamento (PF/CFP)** |

Para **alterar** uma feature existente, use `PROMPT_4A` / `PROMPT_4B`.

> Campos detalhados vivem em `global/DATA-MODEL.md` e requisitos não-funcionais em
> `global/NFR.md` — nunca dentro do N3.
